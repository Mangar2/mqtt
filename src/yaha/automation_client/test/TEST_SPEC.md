# automation_client test specification

## Scope

Unit tests for automation client runtime rule synchronization behavior and INI mapping.

## Test cases

| Name | Scenario | Input | Expected |
|------|----------|-------|----------|
| `automation_component_run_loads_rules_from_filestore` | startup rule load over FileStore HTTP | mock file store returns root with one rule | run loads one rule and hasRule true |
| `automation_component_monitoring_event_reload_rules` | monitor event triggers reload when keyPath matches | changed payload on `$MONITOR/FileStore/changed` with keyPath `/automation/rules` and updated file store payload | in-memory rules are reloaded |
| `automation_component_monitoring_event_reload_rules_for_nested_key_path` | monitor event triggers reload when keyPath points to nested rule path | changed payload on `$MONITOR/FileStore/changed` with keyPath under `/automation/rules/...` and updated file store payload | in-memory rules are reloaded |
| `automation_component_nested_reload_applies_active_false` | nested-rule reload must apply deactivation immediately | first rules payload has `active:true`, then monitor changed event for nested keyPath reloads same rule with `active:false` | first trigger emits once, subsequent trigger emits no additional output |
| `automation_component_management_update_persists_and_acks` | runtime rule set command path | topic `$MONITOR/automation/rules/<name>/set` with JSON payload | rule updated, full tree posted to file store, ack published |
| `automation_component_evaluates_rules_and_publishes_outputs` | domain message triggers full tree evaluation | loaded rule checks `$MONITOR/presence/set` and inbound domain message sets it to `on` | output message is published for matching rule |
| `automation_component_bootstraps_status_presence_initial` | startup bootstrap keeps legacy status/presence initialize rules working | loaded rule checks `status/presence = initial` and first inbound domain message triggers evaluation | output message is published without requiring prior status/presence message |
| `automation_component_get_subscriptions_includes_dynamic_topics` | dynamic and static control subscriptions include parsed external variables and debug namespace | rules payload with check referencing `$MONITOR/presence/set` | subscription map contains `$MONITOR/presence/set` and `$MONITOR/automation/#` |
| `load_automation_client_runtime_config_from_ini` | config mapping for filestore and automation fields | ini with mqtt, filestore and automation entries | parsed config values match inputs |
| `load_automation_client_runtime_config_falls_back_on_invalid_filestore_values_and_uses_legacy_monitor_prefix` | optional filestore values fallback and legacy monitoring prefix mapping | ini with invalid `filestore.port/use/startupRetryCount` and only `monitoring.topicPrefix` set | loader succeeds, defaults are retained for invalid filestore keys, and monitor prefix uses legacy key |
| `load_automation_client_runtime_config_reports_invalid_filestore_retry_values` | filestore startup retry interval range validation | ini with `filestore.startupRetryIntervalSeconds=0` | loader fails and reports field-specific error |
| `load_automation_client_runtime_config_defaults_logging_flags_to_false` | defaults for optional logging switches | ini without automation logging flags | both logging flags in runtime config remain false |
| `load_automation_client_runtime_config_reports_invalid_log_incoming_messages` | invalid bool validation for incoming logging flag | ini with `automation.logIncomingMessages=maybe` | loader fails and reports field-specific error |
| `load_automation_client_runtime_config_reports_invalid_log_outgoing_messages` | invalid bool validation for outgoing logging flag | ini with `automation.logOutgoingMessages=maybe` | loader fails and reports field-specific error |
| `automation_component_logs_incoming_and_outgoing_messages_when_enabled` | runtime logging path for both directions | logging flags enabled, inbound domain message that triggers output | stdout contains shared log lines with `component="automation_client" direction="incoming"` and `component="automation_client" direction="outgoing"`, and outbound reason summary uses the rule identifier |
| `automation_component_management_update_persist_failure_rolls_back_and_acks` | update command with file-store persistence failure | existing stable rule, `POST /automation/rules` returns non-200 | in-memory rules remain unchanged and ack payload is `persist_failed` |
| `automation_component_management_delete_persist_failure_rolls_back_and_acks` | delete command with file-store persistence failure | existing rule, delete payload, `POST /automation/rules` returns non-200 | deleted rule is restored and ack payload is `persist_failed` |
| `automation_component_publish_failure_logs_out_fail_without_false_out_success` | outbound callback throws while outgoing logging is enabled | callback throws on publish and rule evaluation emits message | stderr contains shared outgoing message log markers (`component="automation_client" direction="outgoing"`) with `event=publish_failed` |
| `automation_component_retries_management_ack_after_transient_publish_failure` | first management ack send fails then retry succeeds | callback returns `PublishResult::fail(AckTimeout)` once then success, follow-up inbound message triggers retry loop | ack message is eventually published successfully |
| `automation_component_retry_budget_exhaustion_logs_failure` | retry queue stops after configured max attempts | callback always throws and repeated inbound messages drive retry loop | log contains `category=retry_exhausted` |
| `automation_component_run_with_filestore_get_failure_keeps_empty_rules` | startup load fails with file store GET error | file store returns non-200 for `GET /automation/rules` | component starts, keeps empty rules, and does not crash |
| `automation_component_run_with_filestore_get_404_initializes_empty_rules` | startup load handles missing rules key as non-fatal | file store returns `404` for `GET /automation/rules` | component starts, initializes empty rules object, and does not crash |
| `automation_component_monitor_reload_get_failure_keeps_existing_rules` | monitor-triggered reload fails on file store GET error | existing loaded rule, monitor changed event, then file store returns non-200 | existing rules remain unchanged after failed reload |
| `automation_component_monitor_reload_get_404_keeps_existing_rules` | monitor-triggered reload treats missing key as non-fatal and does not drop current rule set | existing loaded rule, monitor changed event, then file store returns `404` | existing rules remain available after reload attempt |
| `automation_component_flushes_retry_queue_after_callback_restore` | queued publish retries are flushed after callback becomes available again | first management ack is queued due to missing callback, callback set later, next inbound message triggers retry processing | queued management ack is published successfully |
| `automation_component_retries_rule_output_after_publish_result_failure` | rule-output publish path handles explicit failure results (not only exceptions) | callback returns `PublishResult::fail(AckTimeout)` once for `house/light/set`, then success; follow-up inbound message triggers retry loop | rule-output message is eventually published successfully |
| `automation_component_debug_trace_request_reports_not_triggered` | debug request for one rule that does not trigger | topic `$MONITOR/automation/rules/presenceOn/debug` and rule check evaluating false | publishes trace message on matching `/trace` topic, payload `not_triggered`, and non-empty reason trace entries |
| `automation_component_debug_trace_request_reports_anyof_gate_block` | debug request must honor runtime anyOf gate before would-send decision | topic `$MONITOR/automation/rules/presenceOn/debug` and rule with `anyOf` but no matching recent event | trace payload is `not_triggered` and reason contains runtime event-gate skip marker |
| `automation_component_debug_trace_request_reports_allow_gate_block` | debug request must honor runtime allow gate before would-send decision | rule with `anyOf` + `allow`, recent motion topic not in allow set, and debug request on same rule | trace payload is `not_triggered` and reason contains runtime event-gate skip marker |
| `rule_runtime_engine_validates_rule_topic_shapes` | direct rule runtime structure validation for topic forms | non-object rule, missing topic, empty topic, topic array, topic object map | invalid forms return false and valid topic array/object forms return true |
| `rule_runtime_engine_ingests_motion_events_and_trims_history` | direct motion/non-motion event ingestion and trim behavior | zero/non-zero domain messages with motion filters and >100 motion events | zero payload ignored, non-motion set updated, motion history trimmed to max size, and sequence counter advances |
| `rule_runtime_engine_reports_time_gate_errors_and_previews_delivery` | direct time-gate validation errors and delivery-preview controls | rules with invalid time field shapes/expressions and preview rule with delay/cooldown | processing reports errors and preview delivery returns delayed empty then emits with warmed delivery state |

| `automation_component_debug_trace_request_reports_missing_rule` | debug request for unknown rule link | topic `$MONITOR/automation/rules/missing/debug` | publishes trace message on matching `/trace` topic, payload `error`, and reason containing lookup-failed marker |

| `automation_component_debug_trace_request_reports_delivery_control_suppression` | debug request includes whether outbound messages would pass runtime delivery controls | rule emits one output, same value already emitted earlier, then debug request | trace stays `triggered` but reason includes `would send=0` and `delivery controls suppress: dedup/delay/cooldown` |
| `automation_component_debug_trace_raw_payload_escapes_multiline_reason_entries` | debug trace payload keeps reason chain parseable when expressions contain line breaks | rule check contains multiline script and debug request on matching rule | published trace raw payload contains compact explain summary with rule identifier label and without raw newline control characters, and reason entries stay non-empty |
