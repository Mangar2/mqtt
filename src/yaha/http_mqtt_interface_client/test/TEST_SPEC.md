# http_mqtt_interface_client test specification

## Scope

Unit tests for standalone HTTP MQTT interface client INI mapping behavior.

## Test cases

| Name | Scenario | Input | Expected |
|------|----------|-------|----------|
| `load_http_mqtt_interface_client_config_defaults` | default behavior with empty ini | empty INI document | loader succeeds and keeps default values |
| `load_http_mqtt_interface_client_config_from_ini` | explicit field mapping | INI with all `[httpMqttInterface]` keys | loader succeeds and mapped values match |
| `load_http_mqtt_interface_client_config_reports_invalid_port` | numeric bounds validation | `listenerPort=70000` | loader fails with `httpMqttInterface.listenerPort` error |
| `load_http_mqtt_interface_client_config_reports_invalid_alias_flag` | bool parsing for publish.php toggle | `enablePublishPhpAlias=maybe` | loader fails with `httpMqttInterface.enablePublishPhpAlias` error |
| `load_http_mqtt_interface_client_config_reports_invalid_legacy_flag` | bool parsing for legacy response toggle | `useLegacyPhpResponse=invalid` | loader fails with `httpMqttInterface.useLegacyPhpResponse` error |
| `http_mqtt_interface_component_logs_broker_publish_error_when_ack_missing` | broker publish callback fails with ACK timeout and maps to deterministic 500 | POST `/publish` compatibility payload while generic publish callback throws timeout text | response is `500`, and shared outgoing message log contains `event=broker_publish_failed` plus no-ack detail |
| `http_mqtt_interface_component_returns_error_on_listen_failure` | invalid listener host produces deterministic startup failure | component runtime with invalid `listenerHost` | generic runtime throws `YahaError` startup failure |
| `http_mqtt_interface_component_recovers_across_repeated_broker_publish_failures` | repeated broker publish failures must not break long-running request handling | sequence of multiple POST `/publish` requests while publish callback alternates fail/success | responses alternate `500` then `204`, process keeps serving requests |
| `http_mqtt_interface_component_put_publish_failure_returns_500_and_logs` | native PUT publish handler maps dispatcher exceptions to deterministic internal error | PUT `/publish` without supported version headers | response is `500` and error log contains endpoint `/publish` |
| `http_mqtt_interface_component_put_pubrel_failure_returns_500_and_logs` | native PUT pubrel handler maps dispatcher exceptions to deterministic internal error | PUT `/pubrel` without supported version headers | response is `500` and error log contains endpoint `/pubrel` |
| `http_mqtt_interface_component_session_commands_flow` | token-bound full command flow forwards to one broker transport session | PUT `/connect`, `/subscribe`, compatibility POST `/publish` with token, PUT `/receive`, `/pingreq`, `/unsubscribe`, `/disconnect` | command responses are successful, receive returns published payload, and session operations execute on token-bound transport |
| `http_mqtt_interface_component_compat_publish_without_managed_token_uses_legacy_callback` | browser publish path remains unchanged when no managed session token is present | compatibility POST `/publish` without prior connect | request succeeds and injected publish callback is used |
| `http_mqtt_interface_component_command_endpoints_validate_bad_requests` | command endpoints reject invalid payload/token forms deterministically | malformed JSON and missing required fields across `/connect`, `/subscribe`, `/unsubscribe`, `/disconnect`, `/pingreq`, `/receive` | responses return deterministic `400` JSON errors |
| `http_mqtt_interface_component_command_response_mapping_handles_unsupported_version` | dispatcher response mapping errors are converted to deterministic internal errors | valid connect/subscribe/unsubscribe/disconnect requests with `version=9.9` | responses return `500` with endpoint-specific internal error code |
| `http_mqtt_interface_component_compat_publish_managed_session_failure_returns_500` | compatibility publish with managed session token propagates broker publish failure mapping | connect managed session and force managed publish failure on compatibility POST `/publish` | response is `500` and failure mapping remains deterministic |
| `http_mqtt_interface_component_command_options_preflight_endpoints_return_204` | all command OPTIONS preflight handlers return deterministic no-content responses | OPTIONS calls to `/connect`, `/disconnect`, `/subscribe`, `/unsubscribe`, `/pingreq`, `/receive` | each response is `204` with CORS headers |
| `http_mqtt_interface_component_receive_without_message_returns_204` | receive endpoint maps empty broker poll to no-content | connect session and call PUT `/receive` when transport has no incoming message | response is `204` and packet header remains absent |
| `http_mqtt_interface_component_command_response_failed_paths_with_valid_session` | response mapping failures are covered after successful broker operation | connect valid session and call `/subscribe`, `/unsubscribe`, `/disconnect` with unsupported version `9.9` | responses are `500` with `subscribe_response_failed`, `unsubscribe_response_failed`, `disconnect_response_failed` |
| `http_mqtt_interface_component_connect_legacy_host_port_do_not_override_broker_target` | legacy TypeScript connect payload must not redirect broker target | PUT `/connect` with `clientId` plus legacy `host`/`port` and explicit `brokerHost`/`brokerPort` | broker transport receives explicit `brokerHost`/`brokerPort`; legacy `host`/`port` are ignored for broker target |
| `http_mqtt_interface_component_legacy_clientid_commands_without_token` | legacy TypeScript command requests may address session by clientId | connect session, then call `/subscribe`, `/unsubscribe`, `/disconnect` with `clientId` and no token | operations succeed and route to connected session |
| `http_mqtt_session_manager_constructor_without_factory_and_empty_clientid` | default constructor fallback path and input guard | manager with empty transport factory and connect request with empty clientId | connect fails with required-client-id error |
| `http_mqtt_session_manager_connect_overrides_and_disconnect_via_receive_token` | connect stores both tokens and supports receive-token lookup path | connect with host/port/keepAlive overrides, then disconnect using receive token | connect succeeds, overrides are forwarded, and disconnect removes session |
| `http_mqtt_session_manager_connect_failure_paths` | connect error mapping for return-false/std/unknown exceptions | transport connect callback returns false or throws | connect fails with deterministic error text |
| `http_mqtt_session_manager_operation_error_paths` | per-command guard and transport error branches | unknown tokens, missing transport callbacks, std exceptions, unknown exceptions | each command fails with deterministic reason text and false result |
